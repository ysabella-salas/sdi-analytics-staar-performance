Phase I Model Benchmarking: Technical Readout

Phase I tested five model types using the same student data. Two goals guided the work: predict raw scores and predict performance levels.

Key technical outcomes

  • MAP assessment results provide the strongest predictive signal.
  • XGBoost performs best overall; Random Forest remains a strong comparison model.
  • Main risks: uneven class sizes, similar middle performance levels, and possible data leakage.

1. Understand the Data

Score and level patterns

  • Most raw scores sit in the middle range; high scores are less common.
  • Performance levels have uneven counts, especially in the upper bands.
  • Ordered levels support testing an ordinal approach in Phase II.

Predictor patterns

  • MAP achievement measures are the strongest inputs.
  • Student program indicators add useful context.
  • Discipline data is sparse and needs separate zero-value handling.

2. Set the Evaluation Rules

Every model starts with the same predictor set. Comparisons remain valid only when the same evaluation method and metric are used.

Regression track

  • Target: Results Raw Score
  • Key metrics: R2, MAE, and RMSE
  • Review error size across score ranges

Classification track

  • Target: Results Performance Level
  • Key metrics: weighted F1 and ROC AUC
  • Review mistakes between nearby performance levels

Important caveat

Decision Tree results use a different error scale, so direct ranking against R2 or F1 is not valid.

4. Review Errors Before Deployment

Classification errors

  • Most mistakes occur between Approaches and Meets.
  • Large jumps between the lowest and highest levels are uncommon.
  • Separating the middle levels remains the main challenge.

Regression errors

  • Error size changes across different score ranges.
  • Very high scores remain harder to predict than middle scores.
  • Add calibration and score-range checks in Phase II.

5. Improve the Next Model Version

Priority 1: Feature space expansion and data reliability

  • Add TES teacher-linked features for each testing window.
  • Measure match rate, missing values, and lost joins.
  • Add a zero-value flag and capped value for discipline fields.

Priority 2: Objective and validation upgrades

  • Penalize overprediction more heavily than underprediction.
  • Test grouped or time-aware validation to limit leakage.
  • Calibrate model probabilities before setting decision thresholds.

6. Run the Phase II Work Plan

Phase II uses repeatable experiments, a consistent data split, and run tracking to confirm whether XGBoost remains the best model after new features are added.

Next sprint deliverables

  • Finalize the train, validation, and test process.
  • Retrain XGBoost and Random Forest with TES and discipline features.
  • Publish one comparison pack: R2, MAE, RMSE, F1, AUC, calibration, and confusion drift.
Definition of Done: model choice remains stable under stronger validation, with clear error trade-offs and production-ready evaluation artifacts.
